# ransac-plane：算法出处与语义说明

本模块的 C++ 算法（`src/ransac_plane.cc` / `src/ransac_plane.h`）是 **RANSAC 平面拟合的
自研实现**，对外语义对齐 PCL `pcl::SACSegmentation<PointXYZ>` 的
`SACMODEL_PLANE` + `SAC_RANSAC` + `setOptimizeCoefficients(true)` 组合。

## 参考出处

- 项目内保存的文章（原理与参数讲解）：`doc/点云处理RANSAC平面拟合/`
  （PCL RANSAC 平面拟合科普：随机采最小集求解模型、按点到平面距离分内外点、
  迭代取内点支持度最高的模型；`DistanceThreshold` / `MaxIterations` /
  `OptimizeCoefficients` 三个参数）。
- 原始论文：Fischler M A, Bolles R C. _Random Sample Consensus: A Paradigm for
  Model Fitting with Applications to Image Analysis and Automated Cartography_.
  Communications of the ACM, 1984, 24(6):381–395.
- PCL `SACSegmentation` / `SampleConsensusModelPlane` 文档（语义基准，未复制源码）：
  https://pointclouds.org/documentation/classpcl_1_1_s_a_c_segmentation.html
- 自适应迭代次数公式（`N = log(1−p) / log(1−w^k)`）：上述论文与 PCL 的
  `SACSegmentation::initSAC` 实现约定一致（p 默认 0.99）。

## 与上游（PCL / 文章）的差异清单

| 项           | PCL / 文章                                                               | 本实现                                                                           | 理由                                                                                                                         |
| ------------ | ------------------------------------------------------------------------ | -------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| 内点计数范围 | 每轮迭代对**全部**输入点计数（PCL 用候选索引时可传子采样，但默认是全量） | 假设循环只在**采样集**（≤65536 点）上计数；模型定下后再对全量扫描一次            | 1 亿点 × 1000 轮 = 10^11 次距离计算，任何实现都扛不住。见 `ransac_plane.h` 的「两段式」说明                                  |
| 迭代终止     | `maxIterations` 硬性上限 + 同样公式的自适应早停                          | 同左（`kDefaultConfidence = 0.99`），并回传 `iterationsUsed` 供诊断              | 对齐                                                                                                                         |
| 系数优化     | `setOptimizeCoefficients(true)` 对内点集做最小二乘重解                   | 同左，但用协方差最小特征向量（Jacobi）解；且**两版都完整算出后取内点更多的一版** | 最小二乘不是共识最大化，精修后内点数可能变少；直接采用会给出"越优化越差"的结果                                               |
| 法向符号     | 由特征向量/叉积决定，± 不定                                              | 强制「绝对值最大的分量为正」，并连同 d 一起取反                                  | 平面无向，但输出必须确定——否则同一份数据两次运行的法向可能翻向，单测与 3D 法线箭头跟着抖                                     |
| 随机来源     | `std::mt19937`（PCL 默认）                                               | mulberry32（固定种子 `kRandomSeed`）                                             | 32 位纯整数算术，可与 JS `Math.imul` 版本逐位同构，渲染侧单测能镜像；固定种子 ⇒ 同参数结果逐位可复现（预览"只增不减"的基础） |
| 采样去重     | 有放回                                                                   | 有放回                                                                           | 65536 / 1e8 量级下重复抽样期望 < 1 次，去重的代价大于收益                                                                    |
| 退化三点     | PCL 会重试抽点                                                           | 叉积模长相对边长退化（sin∠ ≤ 1e-4）即跳过该轮                                    | 近共线三元组的法向误差被放大 1e-4 倍以上，白跑一轮计数                                                                       |
| 输出         | `ModelCoefficients` + `PointIndices`                                     | 每块内点顶点下标 + 平面模型 + 质量指标 + 平面片画布                              | 渲染侧要画平面片与报平面度；画布跨度若交给渲染侧算，JS 得遍历上亿个内点坐标                                                  |

## 已知局限（**不是 bug，别当 bug 修**）

**均匀采样 RANSAC 找不出占比过低的平面。** 采样集 65536 个点：一个只占全体 0.1% 的平面
大约只会落进 65 个采样点，三点全落在它上面的概率约 (0.001)³ = 1e-9/轮，1000 轮也撞不到。
这是算法本身的固有性质（PCL 同样如此，故它提供 `setInputCloud` + 索引让调用方自行子采样）。

缓解手段（UI 已按此引导，见 `RansacPlaneToolBar.vue` 的 title）：

- **先框选**目标区域再拟合（候选集 = 框选可见点集，`index` 通道天然支持）；
- **先剥掉占比大的平面**（本功能的连续剥离工作流正是为此设计）；
- 调**大距离阈值**（把稀疏的平面也纳入内点）或**调大迭代次数**。

## 与仓库其余原生模块的关系

- 输入契约（`positions` + 可选 `index`、零拷贝 pin、`AsyncWorker` + 内部硬件线程）与
  其余 6 个算法模块**完全同模板**，可直接参考 `native/statistical-filter/src/addon.cc`。
- 输出契约**破模板**：多一个 `plane` 字段（其余模块只回索引数组）。这是继 `lod-octree`
  之后第二处合理的契约偏离——RANSAC 的产物核心是模型而不只是归属。
- 两次全量扫描的并行骨架（`std::thread` 池 + 按块区间均分）沿用
  `statistical-filter.cc` 的 `processRange` 模式，但归约改为**逐块串行归并**（见下）。

## 确定性设计（改代码时别破坏）

1. 采样与三点选取都用**固定种子** mulberry32。
2. 假设循环**单线程**顺序执行——最优跟踪有状态，并行会改变迭代顺序。
3. 两次全量扫描按块并行，但**每块的输出（内点下标数组）由该块独立产出**，
   块内按候选遍历序 → 顶点下标递增，与线程数无关。
4. 全局浮点归约（协方差 9 个累加量、RMS、最大偏差、画布跨度）在**逐块累加器**上做，
   最后按块序**串行**归并 ⇒ 归约顺序也与线程数无关。

于是「同输入同参数 → 逐位相同的输出」。这不是洁癖：预览型交互要求用户微调阈值时画面
稳定地长出来，而不是每预览一次跳一个新结果；单测的确定性断言也依赖它。
