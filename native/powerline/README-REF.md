# powerline：算法出处与语义说明

本模块（`src/powerline.cc` / `.h` / `src/kdtree.h`）是**电力线（导线）提取的自研实现**。

**⚠ 没有上游对应物**：CloudCompare 没有电力线提取功能，PCL 也没有（`pcl::SACMODEL_LINE` 是
三维直线拟合，与"从一片点云里把一根根导线拆出来"不是一回事）。因此本文件**记不了"与上游的差异"**，
只能记自己的判据、实测数字与「别改回去」的理由——这与仓库其余 12 个模块的 README-REF 体例不同，
是模块性的差异，不是遗漏。

参考的只有两条外部线索（都不是源码）：

- 用户提供的流程直觉：**高程初筛 → PCA 线性特征 → 聚类去噪 → 端点补全 → 单条电力线分割**。
  方向正确，但直接照做会卡在两处（见「两条硬约束」），故实际实现是它的**变体**。
- 电力线是**悬链线**、且相邻导线间距 0.3–0.5 m / 单根沿程缺口 1–3 m 这两个几何量级，
  来自输电线路的通用工程常识（也决定了下面所有阈值的取值）。

## 两条硬约束（决定了整个设计）

1. **尺度冲突**：相邻导线间距 0.3–0.5 m，而单根导线沿程（塔身遮挡 / 无回波 / 断股）缺口 1–3 m。
   任何**单一距离阈值**都无法同时做到「分开平行导线」与「不切断单根导线」——
  阈值取 0.5 m 会把每根线切成几十段，取 3 m 会把所有平行线粘成一片。
2. **局部线性不是充分判据**：屋顶脊线、女儿墙、广告牌边框、树枝末端都「局部线性且近水平」。
   城市与穿林场景里，只靠线性度会成片假阳性。

于是本模块的做法是**先连通、再按模型剥离**：用**故意放大**的连接半径（默认 3 m）把候选点
连成片（允许把平行线、交叉线粘在一起），再在片内反复「定方位角 φ → 转到 (s,z) → 稳健抛物线
拟合 → 取内点 = 一根导线 → 剩余点递归」。交叉、平行、毛刺三件事被同一个动作解决，
尺度冲突不再需要单阈值去平衡。

## 两阶段分工与代价层级

| 导出 | 代价 | 做什么 |
| --- | --- | --- |
| `extractCandidates` | **重**（与点数同阶：KD 树 + 逐点 PCA） | HAG 双线性采样 → 离地点集 → KD 树（最长轴中点分裂 / 叶 16）→ 并行 `radiusSearch` → 3×3 协方差 + Jacobi 特征分解 → **宽松闸门**（`linearity ≥ 0.5 && \|v1.z\| ≤ 0.5 && count ≥ 3`）→ 「池子」+ **逐池点特征并行数组** |
| `traceLines` | **轻**（只吃「池子」：几千〜几万点） | 局部方向（`dirRadius`，主向统一到「+x 半空间」符号）→ 角度门限连通（并行并查集）→ 逐片方位角投票 → 抛物线 RANSAC 剥离 → 横向切分 → 端点球面补全 → 编号 |

**为什么特征要回传渲染侧**：「线性度下限 / 最大倾角」是用户最容易反复试的两个旋钮，
把精筛放在渲染侧 ⇒ 拖滑杆只重跑精筛 + `traceLines`（毫秒级），不必重跑 KD 树 + PCA（秒级〜十秒级）。
同 euclidean-cluster 的 `tolerance`（算法参数）vs `minPoints`（渲染侧过滤）分级先例。
代价是回传 4×4 B/池点，可忽略。

**为什么 PCA 邻域建在「离地点集」上而不是「池子」上**：池子是线性度过滤**之后**的结果，
用它建邻域会自我强化——初始漏掉一段导线就再也找不回来（那段点不在任何邻居里，
线性度永远算不出来）。故邻域搜索的底图 = 全部「HAG ≥ 最小离地高」的点。

## 与其余 12 个模块的契约差异

| 项 | 其余 12 个模块 | powerline | 理由 |
| --- | --- | --- | --- |
| **长度 0 的 `index`** | 经 N-API 后（`Data()` 给空指针）与「没有 index」等价 ⇒ native 按**全量顶点**算候选 | **显式区分**：`hasIndex && indexCount == 0` = 该块**零候选** | 非改不可：精筛（线性度/倾角）会把某些块的池子**整个刷空**，若那时退化成"全量顶点"，整块地面/植被都会被当成导线候选去连线（画面直接崩坏）。顺带让 native 与渲染侧 `candidateCountOfChunk` 的语义对齐（那边本来就把长度 0 当 0 个候选）。⚠ 这条**只在本模块**成立，别照着改其余模块 |
| **导出个数** | 各 1 个（registration 3 个、normal-estimate 2 个） | **2 个**（两阶段，见上表） | 参数代价分层，见上 |
| **池子上限** | 无 | `kMaxPoolPoints = 4_000_000`，超限**报错不返回半成品** | 池子超大 ⇒ 下游 `traceLines` 的 KD 树与连通图内存失控。同 LOD 树内存预算拒绝的先例；错误文案引导用户调高「最小离地高」 |
| **`threadCount`** | euclidean-cluster / registration 有 | 有（两个阶段都有） | 仅单测用：钉「结果与线程数无关」 |
| **结果内存** | `memcpy` 进 V8 分配的内存 | 同左（`labels` / `kept` / 四个特征数组都走 `Napi::TypedArrayOf<...>::New` + 拷贝） | **禁用 `napi_create_external_arraybuffer` / `external_buffer`**：Electron 渲染进程的 V8 带 sandbox 会抛 `External buffers are not allowed`，且异常被 node-addon-api 转成"未捕获 JS 异常"，表现为**JS 回调永久不触发** |

`kdtree.h` 是从 `native/euclidean-cluster/src/euclidean_cluster.cc` 里的 `KdTree` 抽出来的
（它本就含 `radiusSearch`），命名空间改 `powerline`——**不动 euclidean-cluster**，避免碰到已绿的模块。
两处副本将来若要合并，前提是先有一个共享头目录，本轮不做。

## 关键判据与「别改回去」清单

1. **用「垂直平面抛物线」而不是 3D 直线拟合**。导线是悬链线：300 m 跨、8 m 垂度下直线拟合的
   最大残差就是 8 m，完全失效。抛物线与悬链线在典型垂跨比（垂度/跨长 < 0.05）下偏差在
   **1e-3 相对量级**（合成场景垂跨比 0.03，实测残差 RMS 在 mm 级），且**线性最小二乘可解**。
   抛物线建模在导线自身的竖直平面 (s, z) 里：`z = a·s² + b·s + c`。
2. **方位角投票不是票数 argmax**。方位角 φ 由片内局部方向按**票数占比 × 各向异性比**分箱投票
   （60 箱 / 3°；取前 3 个峰逐个试拟合取最优）。理由与 `native/ransac-cylinder` 的轴方向判据同源：
   票数 argmax 会让"躺在平面里的每个方向"免费投票（地面主导的点云里必然选错）。
3. **三点拟合要求采样跨度**：`kSampleSpanFraction = 0.35`（三点在 s 方向铺开的跨度必须 ≥
   片内 s 跨度的 35%）、`kSampleMinDeltaS = 0.5` m（两两 |Δs| 下限）。三点紧挨着取样时
   Vandermonde 矩阵条件数与 `(s1−s2)(s2−s3)(s1−s3)` 同阶 ⇒ 解出的 a 巨大、曲线在采样点外
   迅速偏离。**别为了"提高内点率"放宽这两条**——放宽后 `d/S < 0.35`，误差回到 σ 量级以上，
   内点率看着变高而拟合其实已经不可信。
4. **平行线只能靠横向 t-gap 分开**（`kLateralGapM = 0.30` m）。同一横担上的两根导线
   **z(s) 完全相同**——抛物线残差对它们毫无分辨力（都在容差内），靠残差永远分不开。
   故剥离出跨段后还要在横向坐标 t 上切一刀：相邻导线间距 0.3–0.5 m（切得开）、
   单根线自身的横向散布 ≤ 0.2 m（切不开）。切完再对每段做横向直线拟合，用
   `kWireLateralRms = 0.35` m 挡住"散点组成的厚带"被当成一根线。
5. **连通的方向门限 `kConnectAngleGateDeg = 15°`**：局部主方向夹角超过它的两点不连——
   交叉线（≈90°）由此**天然断开**，不必等抛物线剥离去拆。这是"交叉处被正确切成两条"的第一道保证。
6. **端点补全的三重门限**：连接向量与两侧切向夹角 ≤ `gapAngleDeg`（默认 12°）、
   横向偏移 ≤ `kLateralTolerance = 0.5` m、同一对端点只连一次取最优。缺了横向门限就会把
   "平行但错开的另一根线"接上（拐一个折角）；缺了角度门限会把"塔另一侧的另一根线"接上。
7. **剥离必须把内点从 `active` 移除**（且每片最多 `kMaxStripsPerComponent = 64` 次剥离）。
   内点若不摘掉，下一轮还会拟合出同一条曲线——**死循环**。这条是终止性的保证，不是优化。
8. **残差内点判定用 `|z − z_model(s)| ≤ residualTolerance`（含等号）**，坐标全程 `double`。
   C++ 全用 double + 基本算术，故合成场景能断言"HAG 与解析式一致到 1e-3"这类逐元素结论。

### 实测踩过的坑（都在合成场景里复现过）

- **采样集不放回**不适用于本模块（与 `ransac-cylinder` 相反）：三点拟合的采样是
  "按跨度分层抽三点"，本来就不重复；有放回会让同一点被抽两次而白费一轮（`kSampleMinDeltaS` 会挡掉，
  但轮数是白花的）。
- **`fillHoles` 的均值填充会系统性低估地面**：多源 BFS 用"已定值 4 邻居的均值"填洞，
  在斜坡上会把邻格的滞后一路传下去。实测（5% 坡、10 m 格、地面点只有 3 排 × 每隔 10 m 一个）
  空洞处的填值比真值**低约 0.85 m**。方向是**安全侧**：填低了 ⇒ HAG 偏大 ⇒ 多留点
  （宁可多留，见下条），不会静默丢导线。故这是**已接受**的行为，不是缺陷；
  要收紧就加密地面点（真实 LAS 的地面点覆盖率远高于该测试）。

## 实测记录（合成场景，`tests/unit/renderer/utils/powerline.spec.ts`）

场景：起伏地面（沿 x 的 5% 斜坡）+ 3 条解析悬链线（两条**平行**沿 x、间距 4 m；一条沿 y
**横穿**它们，交叉点高差 ≈ 1 m，落在连接半径之内）+ 2 基塔（4 条竖腿 + 2 根 10 m 横担）+
6 个树冠团簇 + 15 m 女儿墙 + 800 个随机散点。参数：`radius = 2`、其余默认。

| 断言 | 实测 |
| --- | --- |
| **线数 == 3**（平行分离 ✓ 交叉分离 ✓） | 3 条线、3 个不同线号 |
| 每条导线**自成一条线**（不被拆成多段） | ✓（同一条导线的所有成线点只有一个 line id） |
| 每条导线的召回率 | **0.980 / 0.980 / 0.953**（断言 ≥ 0.95） |
| 结构化干扰（塔腿 / 横担 / 树冠 / 女儿墙） | 成线点数 **0** |
| 随机散点的假阳性率 | **< 2%** |
| 端点补全 | 跨中挖掉 17 个点（8 m 缺口）⇒ 仍是一条线且 `gapCount ≥ 1`（点数少 15–19 个，即只丢缺口本身） |
| 确定性 | 同参数两次运行 `labels` **逐位相等** |
| 线程无关 | `threadCount` 1 vs 4 **逐位相等** |
| 分块不变性 | 同一片云切 1 / 3 / 7 块 **逐位相等** |
| HAG 闸门真的在用地面参考面 | 参考面抬高 30 m ⇒ `offGroundCount == 0`（对照 > 2500，实测 ≈ 3514） |
| 池子上限 / 越界 index / 非 3 倍数 positions | 报错或空结果，**不崩、不返回半成品** |

**召回率不是 1.0 是已知且可接受的**，丢点机制只有一条：PCA 邻域（半径 2 m）里混进"别的方向"，
线性度就从 1.000 掉下来——

- 散点贴着导线 ⇒ 线性度 0.77~0.85（实测丢 6 点/根）⇒ 默认精筛 0.85 判掉；
- **另一根导线在交叉处斜穿邻域 ⇒ ≈0.5**（实测丢 17 点）——90° 交叉是**最坏**情形。

丢掉这些点**不会拆断线**（端点补全把断口接上，`gapCount ≥ 1`），它们落进 `<源名>.noise`，
于是「各线实体 ∪ `.noise` == 源点云」仍然成立。**想零丢失**就把渲染侧的「线性度下限」滑到 0.5
（= native 宽松闸），代价是候选池变大、`traceLines` 变慢。

## 已知限制（诚实清单）

1. **超过最短线长的干净直屋脊 / 围栏会被当成一条线**。合成场景里加一条 40 m 的水平围栏，
   它**确实**会被提取出来（实测 4 条线）。三道闸（抛物线残差 / 最短线长 / 补全共线）能滤掉
   "不干净"或"太短"的假阳性，但"长、直、干净、近水平"的结构与导线在几何上不可区分。
   下一轮的修法是加**垂度门槛/垂直空隙判据**（真导线有下垂，围栏没有），本轮只把 `sag` 上报为统计量。
2. **点密度相关性**：`radius` 按整体平均点距估（×10），而导线点本身很稀疏（ALS 4–8 点/m²）——
   稀疏数据要手调。邻域半径的「自动」按钮留到下一轮（照 `normal-estimate#guessRadius`）。
3. **DTM 系统偏差**：陡坡 / 密林下地面点少，HAG 会有米级误差 ⇒ 默认 4 m 偏保守（宁可多留）。
4. **耗时**：`extractCandidates` 在 5000 万点量级预估 5–20 s，本轮**只有 console 日志、没有进度条**
   （已知取舍；换 `AsyncProgressWorker` 的改动很小，csf-pro 已有先例）。
5. **后处理吸收**：被精筛判掉的导线点（见上「召回率」）目前只能落进 `.noise`。
   要"吸回去"得把各线的抛物线模型导出到渲染侧再逐点判定距离，本轮不做。
6. **参数默认值是经验值**，必须用真实数据校准后再固化（合成场景验的是算法正确性，不是调参）。

## 内存与耗时量级

- 阶段 1：离地点集的连续副本 12 B/点 + 候选码 4 B/点 + KD 树（叶 16，约 4 B/点）；
  池子 ≤ `kMaxPoolPoints`。逐点 PCA 是 3×3 协方差 + Jacobi（固定 8 轮以内），
  候选数 ≥ 20 万时按硬件线程数分段并行（`kParallelMinPoints`）。
- 阶段 2：只吃池子，候选集的连续副本 + 连通图的父指针 4 B/候选（`std::atomic<uint32_t>`，
  小根优先 CAS + 路径减半）——并行但**结果与线程数无关**（根 = 分量内最小候选号，
  同 euclidean-cluster）。剥离循环是逐片串行（片内递归剥离有依赖），片的并行度来自
  片之间互相独立，本轮未并行（池子只有几千〜几万点，不值得）。
