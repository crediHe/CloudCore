# ransac-cylinder：算法出处与语义说明

本模块的 C++ 算法（`src/ransac_cylinder.cc` / `src/ransac_cylinder.h`）是 **RANSAC 圆柱拟合的
自研实现**，对外语义对齐 PCL `pcl::SACSegmentationFromNormals<PointXYZ, Normal>` 的
`SACMODEL_CYLINDER` + `SAC_RANSAC` + `setOptimizeCoefficients(true)` 组合。

## 参考出处

- 项目内保存的文章（原理与参数讲解）：`doc/点云处理RANSAC圆柱拟合/`
  （PCL RANSAC 圆柱拟合科普：7 参数定义圆柱、随机采最小集求解模型、按点到圆柱面距离分内外点、
  迭代取内点支持度最高的模型；`DistanceThreshold` / `MaxIterations` / `Probability` /
  `OptimizeCoefficients` / **`RadiusLimits`** / **`Axis`** 六个参数与「新手调参口诀」）。
- 原始论文：Fischler M A, Bolles R C. _Random Sample Consensus: A Paradigm for
  Model Fitting with Applications to Image Analysis and Automated Cartography_.
  Communications of the ACM, 1984, 24(6):381–395.
- PCL `SACSegmentationFromNormals` / `SampleConsensusModelCylinder` 文档（语义基准，未复制源码）：
  https://pointclouds.org/documentation/classpcl_1_1_s_a_c_segmentation_from_normals.html
- 自适应迭代次数公式（`N = log(1−p) / log(1−w^k)`）：上述论文与 PCL 的
  `SACSegmentation::initSAC` 实现约定一致（p 默认 0.99）。
- Kåsa 代数圆拟合：Kåsa I. _A circle fitting procedure and its error analysis_.
  IEEE Transactions on Instrumentation and Measurement, 1976, 25(1):8–14.
  （`x² + y² = 2c₁x + 2c₂y − k` 对 (c₁, c₂, k) 线性，正规方程 3×3 闭式求解。）
- 「表面法线二阶矩求轴」这一轴方向估计路线是本模块自研的（见下）：**调用方提供的**法线
  （`normalCode` 量化码）→ 两两叉积投票定候选方向 → 一致法线集 `Σnnᵀ` 的最小特征向量精修。
  它的数学根据是标准结论（圆柱面法线 ⊥ 轴 ⇒ 法线二阶矩的最小特征向量即轴向），本实现独立写出。
- **投票判据里的「各向异性比」是本模块自研的修正**（2026-09，见下「轴方向怎么来的」）：
  候选方向按「票数占比 × 一致法线的 λ_mid/λ_max」排序。它没有对应文献，是实测（地面主导场景
  系统性选错轴）逼出来的——平面法线只有一个方向、柱面径向法线在 ⊥ 轴面内各向同性，比值恰好
  把两者分开。备选做法与实测数据都记在该节，**不要退回按票数 argmax**。
- 被否决的备选（见下「轴方向怎么来的」）是「投影协方差各向异性最小化」，代码已删除、**不要
  改回去**；**局部法线现算**（网格 + kNN + 局部 PCA）也曾是本模块的一部分，2026-09 删除，
  改为吃调用方的法线通道。相关的无约束 5 点解法（同样未采用，风险过高）见 Beder C.
  _Estimating the parameters of a cylinder from five points_, Graphics Geometry Preprint 2006；
  Zsombor-Murray P, El Fashny K. _A Cylinder Model from Five Points and Some Computer Vision
  Applications_.

## 轴方向怎么来的（本模块最实质的自研部分）

路径是「**表面法线**」，因为圆柱面的每个法线都 ⊥ 轴：取采样集法线的二阶矩 `Σnᵢnᵢᵀ`，
其**最小特征向量**就是轴方向。这个估计器是**精确**的（不是启发式），且有两个好性质：

- 叠加各向同性污染（噪声、球状外点云）只是给所有特征值加同一个常数，**不转动特征向量**；
- 法线的正负号无意义（`n` 与 `−n` 同一条线），而 `nᵢnᵢᵀ` 与叉积都对符号不敏感 ⇒ 无需定向。

**法线从哪来（2026-09 起）**：不再是本模块现算的，而是**调用方传入**——每个 chunk 带一份
`normalCodes: Uint16Array`（**顶点缓冲空间**，与渲染侧 `normalCode` 属性同布局），本模块用
`normal_compressor.h` 的 `decompressNormal` 解码并**归一化**（解码出的是箱角之和、模长约 1/√3，
不归一化会让下游 `n² > 0.5` 的合法性判据全部失效），`NULL_NORM_CODE` 解出零向量（= 无法线）。
量化码的精度不是瓶颈：`Σnnᵀ` 是平均估计器，单法线 0.3~0.5° 的量化误差在 N 个法线上摊成
`0.5°/√N`。法线的来源算法是渲染侧的 `Edit ▸ Normals`（`native/normal-estimate`，CC 对齐），
本模块只消费结果；这同时让「估轴的输入」对用户**可见可调**（半径、LS/Quadric 都在那个对话框里）。

实现分三步（都在**采样集**上，≤65536 点）：

1. **取法线**：采样循环顺带解出（块、块内候选）→ 顶点下标 → `normalCodes[vertex]` → 解码
   → 归一化。零向量（NULL 码 / 退化）不参与投票。
2. **粗定方向**：法线两两叉积投票（`n₁ × n₂` 就是轴向候选）。投票是 RANSAC 式的——固定种子
   PRNG 抽对、按 `|n·a| ≤ 0.05` 数票；候选按下面这个**得分**排序，不是按票数：

   ```
   得分 = 票数 / 有效法线数  ×  λ_mid / λ_max(一致法线集的二阶矩)
   ```

   **第二项是必须的**（2026-09 修正，见下表实测）。只用票数是坏的：平面（地面）的法线**全部
   垂直于该平面内的任何方向**，于是每个躺在平面里的方向都免费拿到全部平面法线的票——地面占
   九成的点云里，真轴反而票少，系统性选错。而一致法线的二阶矩把两者分得干干净净：

   - 平面法线只有一个方向 ⇒ 另两个特征值 ≈ 0 ⇒ 比值 ≈ 0；
   - 柱面径向法线在 ⊥ 轴的面内各向同性 ⇒ 另两个特征值相等且远大于最小者 ⇒ 比值 ≈ 1。

   认轴另有**得分闸门** `kMinAxisScore = 0.02`（实测：垃圾候选最高 0.0088、合法最低 0.023
   ——窄圆弧无竞争时的那种，留 ~2.6× 余量），票数闸门 `kMinAxisVotes = 16` 仍然保留。
   投票轮数有下限 `kMinVoteIterations = 256`：早停用的是**最优候选**的票数占比、而非第一名，
   且「管壁 × 管壁」这种对子要 ~~1/p² 轮才抽得到（p = 圆柱占比，10% 时 256 轮的期望命中
   ≈ 2.6 对，成功率 ≈ 92%）——没有这个下限，占比 0.9 的平面会让它在第 2~~3 轮就 break。

3. **精修两轮**：按 `|n·a| ≤ 0.08`（再 `≤ 0.035`）收缩内点，各自重解 `Σnnᵀ` 的最小特征向量。
   精修在**内点集**上再做一遍（与第 ①/② 步同一套代码，输入换成已判为内点的采样点法线）。

2026-09 实测（真产物，6 万点，水平地面 + 半径 0.3 的圆柱）：

| 场景               | 旧：票数 argmax        | 旧：换成实体法线后**仍按票数** | 新：票数 × 各向异性比 |
| ------------------ | ---------------------- | ------------------------------ | --------------------- |
| 地面 + 竖直管 10%  | **90.0°** ✗            | 68.7° ✗                        | **0.6~1.2°** ✓        |
| 地面 + 倾斜管 10%  | **72.5°** ✗            | 仍错（同款系统性偏）           | **1.2°** ✓            |
| 地面 + 倾斜管 30%  | **72.2°** ✗            | —                              | **0.7°** ✓            |
| 地面 + 水平管 30%  | 0.7° ✓                 | —                              | 0.6° ✓                |
| 纯地面（无圆柱）   | 假大圆柱（半径 13665） | —                              | 得分 0 ⇒ **判未找到** |
| 纯倾斜管（无地面） | 0.4° ✓                 | —                              | 0.9° ✓                |

这张表里第二列是本次最贵的一课：**只把法线换成"更好的"来源，一点也不改善**——1° 的法线喂给
坏判据，输出的仍是坏轴。轴估计的老断言（合成倾斜圆柱 + 噪声 + 离群点，见
`tests/unit/renderer/utils/ransacCylinder.spec.ts`）轴偏差 ≤ 0.08° 仍成立（那里没有平面竞争）。

> **注意「纯地面 ⇒ 各向同性比值 ≈ 1」这一条**：随机朝向的法线里，落在 `|n·a| ≤ 0.05` 带内的
> 占比恰为 0.05，且该带内 `Σnnᵀ` 是各向同性的 ⇒ 得分 ≈ 0.05 **高于** 0.02 闸门。这是刻意留的：
> 这种输入下"轴"本无意义，闸门只负责挡掉平面主导的假轴；真正决定能不能收出东西的是后面的
> RANSAC（纯地面会收出半径远大于点云尺度的"圆柱"，用户靠 `maxRadius` 挡，与显式轴模式同款风险）。

### 被否决的方案（**别再改回去**）

1. ~~**PCA 主轴**~~——细长圆柱上它确实指向轴线，但**短粗圆柱上主轴不再指向轴线**
   （长度 ≲ 直径时轴向方差小于径向），且外点一多主轴就被拉偏。
2. ~~**逐个假设采样方向**~~——会破坏 `w³` 早停模型（样本量不再是常数 3），且方向空间是二维
   连续量，随机撒点的收敛速度比闭式搜索差，还要把方向估计叠进假设循环。
3. ~~**模块内现算局部法线**~~（网格 + kNN + 半径启发式 + 局部 PCA，2026-09 删除）——不是"错"，
   是**重复且更弱**：渲染侧已经有 CC 对齐、可调半径、带 Auto 与 LS/Quadric 的正式法线估计
   （`native/normal-estimate`），结论还能存下来复用；模块内那份既看不见也改不了，还把它
   和 RANSAC 的采样集绑死。删掉后本模块只解码量化码，`normal_compressor.{h,cc}` 随之拷入。
4. ~~**投影各向异性最小化**~~——曾实现（`f(a) = (λ₁−λ₂)²/(λ₁+λ₂)²`，λ 为投影协方差 `P·C·P`
   的两个非零特征值；`P = I − aaᵀ`）：写得又短又漂亮，**每个候选方向 O(1)**（由 `C` 的迹与
   平方迹闭式算出，与点数无关），于是喂了「协方差特征向量 + 256 个黄金角螺旋播种 + 8 邻域
   切线模式搜索」这种密集确定性搜索，收敛到 0.006°。

   **但它的全局最小值不在真轴上。** 轴向的方差泄漏进投影面，恰好抵消本征的径向特征值差
   ——两个效应在 `sin²θ ≈ 0.006` 处相消，伪零点落在真轴前约 **4.5°**（目标函数值算得**完全
   正确**，0.00% 误差；错的是它最小的地方）。实测外点稍多时轴偏 **17°**、20000 个内点只收到
   852 个。这不是实现 bug，是目标函数本身的性质：**任何「投影协方差特征值之差」式的目标都有
   这个伪零点**，因为投影面里同时装着「径向的本征差」和「被斜切进来的轴向方差」。

   教训值得留着：目标函数「数值算得对」与「最小点是对的」是两件事。当时的自检只验证了
   `f` 在给定方向上的**取值**与暴力计算一致，没验证**极小点**落在哪——函数值全对，方案全错。

   ⚠ 别把它和本模块现在用的「**法线二阶矩**各向异性比」混为一谈：那个是**打分**用的标量
   （λ_mid/λ_max，来自 `Σnnᵀ`，与投影、与候选方向的邻域搜索都无关），不构造任何伪零点；
   它只决定"这个候选轴的票值不值钱"，不参与"往哪个方向微调"。上面这个伪零点出在
   **目标函数的极小点位置**上。

## 已知局限（**不是 bug，别当 bug 修**）

1. **由法线估轴依赖「法线里确实有圆柱面」。** 投票靠**成对法线**：圆柱占比 p 时一轮抽到
   「两个点都落在圆柱上」的概率是 p²，所以 p ≲ 5% 时 256 轮轮数下限内也基本抽不到对子，
   得分只能贴着闸门走，结果是判未找到（而不是给出一个错轴——得分闸门就是干这个的）。
   接地气的说法：**占比低就先框选局部再拟合，或先剥掉占比大的结构**。法线本身的质量也在这
   一条里：没算法线的实体走这条路会被硬拒（native 抛 `TypeError`），覆盖不足则渲染侧禁用预览。
2. **均匀采样 RANSAC 找不出占比过低的圆柱。** 与 ransac-plane 同源：一个只占全体 0.1% 的
   圆柱，三点全落在它上面的概率约 (0.001)³/轮，1000 轮也撞不到（PCL 同样如此）。
   缓解手段：先框选、先剥掉占比大的结构、调大距离阈值或迭代次数。
3. **Kåsa 代数解对部分弧有轻微半径偏差。** 只扫到半个圆周时，代数拟合的半径略偏小
   （仍**明显优于**「取质心当圆心」——后者在半圆时质心偏离达 0.36r），但不是无偏估计。
   需要更高精度请缩小距离阈值并依赖精修，或改用 PCL 的 LM（本实现刻意不手写 LM，见差异表）。
4. **默认不限制半径，可能拟合出"大得离谱"的圆柱。** 被近共线三元组解出的近平面圆柱（半径
   → 很大）只有在设置了 `maxRadius` 时才会被拒。文章对此的原话是「禁止在无半径约束的场景下
   运行算法」——UI 的半径输入框 title 已带这条提示，但默认值仍留空（不替用户静默设界）。
   注意这不只是显式轴那一档的问题：**轴一旦与一片主导平面平行，那片平面就落在「R→∞ 的圆柱」
   的切平面上**，于是法线估轴也会撞上它。实测「水平地面 + 半径 0.3 的水平管」（地面:管 = 9:1）
   在没有 `maxRadius` 时给出 R = 1085~~2970、吞掉 5300~~5462 个地面点（真圆只有 2667 个管壁点），
   **轴方向仍是对的**（0.43°）——也就是说这是支撑数意义上的合法胜出，不是判据错。
   加上 `maxRadius = 1` 后真管立刻回来（R = 0.3002）。`ransacCylinder.spec.ts` 有一条用例
   把这两面都钉住（轴仍准 + 限半径后半径复原）。
5. **纯直线点集不会拟合出半径 0 的假圆柱。** 三点共线时投影行列式退化 → 该轮直接跳过，
   故「一条线」得到的是 `found = false`，而不是一个退化的零半径圆柱。

## 与仓库其余原生模块的关系

- 输入契约（`positions` + 可选 `index`、零拷贝 pin、`AsyncWorker` + 内部硬件线程）与
  其余 7 个算法模块**完全同模板**，可直接参考 `native/statistical-filter/src/addon.cc`；
  2026-09 起每块还可带 `normals`（`Uint16Array`，顶点缓冲空间，长度必须 = 该块顶点数），
  同样是 `Napi::Persistent` 零拷贝 pin。**`axis` 为 null 时它是必填**：缺了直接抛 `TypeError`
  （干净失败，不让半截输入算出一个假轴）。
- **`src/normal_compressor.{h,cc}` 是从 `native/normal-estimate/` 整份拷来的**（只改了
  namespace）——仓库惯例是 native 模块各自自包含、不建共享目录。代价：`QUANTIZE_LEVEL` 等
  量化常量现在是**三处同步**（两份 C++ + `src/renderer/utils/normalEstimate.ts` 的
  `NORMAL_QUANTIZE_LEVEL`），改一处必须三处一起改。本模块只用 `decompressNormal`（`compress`
  留着是为了整份拷贝、便于两边 diff 对齐）。
- 输出契约**破模板**：多一个 `cylinder` 字段（含 `axisEstimated` / `axisScore`，与 ransac-plane
  的 `plane` 同理）。算上 lod-octree 的输入形态偏离，这是第三处合理的契约偏离——RANSAC 的
  产物核心是模型而不只是归属。
- 两次全量扫描的并行骨架（`std::thread` 池 + 按块区间均分）沿用 `statistical-filter.cc` 的
  `processRange` 模式，但归约改为**逐块串行归并**（见下）。

## 确定性设计（改代码时别破坏）

1. 采样与三点选取都用**固定种子** mulberry32（两处用不同子序列，避免三点落在关联位置上）。
2. 假设循环**单线程**顺序执行——最优跟踪有状态，并行会改变迭代顺序。
3. 两次全量扫描按块并行，但**每块的输出（内点下标数组）由该块独立产出**，
   块内按候选遍历序 → 顶点下标递增，与线程数无关。
4. 全局浮点归约（一/二/三阶矩、RMS、最大偏差、轴向范围）在**逐块累加器**上做，
   最后按块序**串行**归并 ⇒ 归约顺序也与线程数无关。
5. 轴方向的估计里，**只有投票一步用随机**（固定种子 `kRandomSeed ^ 0x51ED2701u`，与采样、
   与三点选取各用不同子序列），其余（解码量化码、`Σnnᵀ` 精修、Kåsa）都无随机成分；投票有
   票数、轮数（`kMinVoteIterations` ~ `kMaxVoteIterations`）三处硬上界，且早停判据只看
   最优候选。抽对顺序固定 ⇒ 同一份数据必得同一个方向 ⇒ 预览稳定。
6. 采样**不放回**：抽取顺序即样本序，对同一输入完全可复现（放回版的重复重数也是确定的，
   但它让三元组更容易近共线、也让选票分布被重数主导，见差异表）。

于是「同输入同参数 → 逐位相同的输出」。这不是洁癖：预览型交互要求用户微调阈值时画面
稳定地长出来，而不是每预览一次跳一个新结果；单测的确定性断言也依赖它。

## 为什么扫描要顺带累加三阶矩（改扫描循环时别删）

精修的 Kåsa 圆拟合需要 `x³ / x²y / xy² / y³` 这些**三阶**累加量。若在扫描时按当时的 (e₁, e₂)
基累加，轴方向一变基就变，就得**再扫一遍全量数据**。改为累加**以扫描模型轴点为原点的
二、三阶矩张量**（2 阶 6 个 + 3 阶 10 个独立分量），则**任意**正交基下的
`(Sx, Sy, Sxx, Sxy, Syy, Sxz, Syz)` 都能闭式收缩得到（`contractMoment3`），精修不再需要额外扫描。
代价只有「每个**内点**多约 40 flop」。

## 2026-09 修的符号错误：Kåsa 的半径回代（**别改回去**）

`kasaCircle` 解出的是圆方程的系数 `(c₁, c₂, k)`，圆方程 `x² + y² = 2c₁x + 2c₂y − k` 配方后为
`(x−c₁)² + (y−c₂)² = c₁² + c₂² − k`，故 **`r² = c₁² + c₂² − k`**。原实现写成了
`r2 = k + c₁² + c₂²`（k 的符号反了），于是 `r2 = 2(c₁²+c₂²) − r²`：
**参考点到真圆心的距离小于 `r/√2` 时 `r2 < 0`，`refineCircle` 直接 `return false`**。
而参考点就是上一版模型的轴点、正常情形下几乎就在轴上 ⇒ 只有"圆心离轴点极远"的病态模型
（半径上千的贴地假圆柱）才碰巧通过。

症状是**静默的**：不报错、不崩，只是精修那一版永远不参与 `scan1.count > scan0.count` 的比较，
等于「系数优化」这个勾选项什么都没做。质量断言当初全绿，因为粗定模型本来就够好
（轴由投票 + `Σnnᵀ` 定，1e-6 量级的断言靠的是那一步，不是精修）。改对之后立竿见影：

| 用例（合成数据）        | 精修失效（旧）                                | 精修生效（今）                                         |
| ----------------------- | --------------------------------------------- | ------------------------------------------------------ |
| 70000 点圆柱、阈值 0.02 | R = 2.502468、中心偏 1.4e-2、**丢 1017 个点** | R = 2.500062、中心偏 1e-4、**一个不丢（70000/70000）** |
| 地面 + 竖直管 10%       | R = 0.2932                                    | R = 0.3000                                             |

改扫描循环或 `kasaCircle` 时留意：它的失败路径是**保留上一版模型**（这是刻意的兜底语义），
所以符号写错不会以任何形式报出来。`ransacCylinder.spec.ts` 里那条「候选全部为内点时
inlierCount > 69000」的回归防线就是它的哨兵（失效时 68983、生效时 70000）。
